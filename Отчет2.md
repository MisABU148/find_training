## Развёртывание приложения в Kubernetes

### 1. Использованные абстракции Kubernetes

Для развёртывания приложения Find Training в Minikube использованы следующие абстракции Kubernetes:

* **Deployment** — управляет созданием и состоянием Pod приложения. Созданы отдельные Deployment для PostgreSQL, backend и frontend. Для frontend установлено две реплики, для backend и PostgreSQL — по одной.
* **Pod** — минимальная запускаемая единица Kubernetes, содержащая контейнеры приложения. В Pod frontend запускается React-приложение, обслуживаемое Nginx; backend работает на Spring Boot, а база данных — на PostgreSQL.
* **Service** — обеспечивает сетевой доступ к компонентам приложения внутри кластера. Созданы сервисы `postgres`, `backend` и `frontend` типа `ClusterIP`.
* **ConfigMap** — хранит настройки приложения, не являющиеся секретными. В нём заданы имя базы данных, JDBC URL, порт backend и параметр `JPA_DDL_AUTO`. Отдельный ConfigMap содержит конфигурацию Nginx для frontend.
* **Secret** — хранит учётные данные PostgreSQL, используемые при запуске базы данных и подключении backend.
* **PersistentVolumeClaim (PVC)** — запрашивает постоянное хранилище для PostgreSQL, чтобы данные базы не зависели от жизненного цикла отдельного Pod.
* **Init Container** — перед запуском backend проверяет доступность PostgreSQL и ожидает готовности базы данных.
* **Readiness Probe, Liveness Probe и Startup Probe** — позволяют Kubernetes проверять готовность и состояние контейнера backend. Для frontend настроены проверки доступности HTTP-страницы.

### 2. Взаимодействие сервисов приложения

Приложение состоит из трёх основных компонентов: frontend, backend и PostgreSQL.

1. Пользователь открывает frontend в браузере. Для доступа к приложению в Minikube используется команда `kubectl port-forward service/frontend 8090:80`, после чего приложение доступно по адресу `http://localhost:8090`.
2. Frontend представляет собой React-приложение, собранное для production и обслуживаемое Nginx. Nginx принимает HTTP-запросы на порту 80.
3. Запросы к API с префиксом `/api/` Nginx перенаправляет на сервис `backend` по адресу `http://backend:8080`. Имя `backend` разрешается во внутренний адрес Kubernetes Service.
4. Backend — приложение на Java и Spring Boot, которое обрабатывает REST API-запросы. Оно подключается к PostgreSQL по JDBC URL `jdbc:postgresql://postgres:5432/appdb`.
5. Имя `postgres` разрешается в адрес Kubernetes Service базы данных. Сервис перенаправляет запросы на порт 5432 Pod PostgreSQL.
6. При запуске backend ожидает доступности PostgreSQL. Flyway выполняет миграции базы данных, определённые в ресурсах backend-приложения.
7. Ответ от backend возвращается через Nginx во frontend, после чего результат отображается пользователю.

Схема взаимодействия:

```text
Браузер пользователя
        |
        | HTTP :8090
        v
Service frontend (ClusterIP :80)
        |
        v
Pod frontend (React + Nginx)
        |
        | HTTP /api/* -> backend:8080
        v
Service backend (ClusterIP :8080)
        |
        v
Pod backend (Spring Boot :8080)
        |
        | JDBC :5432
        v
Service postgres (ClusterIP :5432)
        |
        v
Pod PostgreSQL
        |
        v
PersistentVolumeClaim (PVC)
```

### 3. Конфигурация и сетевой доступ

Внутреннее взаимодействие компонентов организовано через Kubernetes Services. Благодаря этому backend обращается к базе данных по имени `postgres`, а Nginx обращается к backend по имени `backend`, без необходимости указывать IP-адреса Pod.

Frontend доступен с локального компьютера через `kubectl port-forward`. Внутренние сервисы backend и PostgreSQL имеют тип `ClusterIP` и не публикуются напрямую наружу.

Настройки приложения передаются через ConfigMap и Secret. Для локального развёртывания используются образы `find-training-backend:1.0` и `find-training-frontend:1.0`, предварительно загруженные в Minikube. Для них указана политика `imagePullPolicy: Never`, чтобы Kubernetes использовал локальные образы.

### 4. Проверка развёртывания

После применения манифестов командой `kubectl apply -f k8s/app.yaml` проверено состояние ресурсов Kubernetes.

Для проверки использовались команды:

```bash
kubectl get nodes
kubectl get deployments
kubectl get pods -o wide
kubectl get services
kubectl get pvc
kubectl logs deployment/backend
```

Дополнительно проверена доступность frontend через браузер и выполнена проверка API через frontend-прокси. Масштабирование Deployment frontend и удаление одного из frontend Pod позволяют продемонстрировать управление количеством реплик и автоматическое восстановление Pod контроллером Deployment.

Таким образом, приложение Find Training развёрнуто в Minikube с использованием основных абстракций Kubernetes, а взаимодействие между frontend, backend и PostgreSQL организовано через внутренние сервисы кластера.
